# 임베딩 모델 비교 측정 결과 (KR-SBERT 전환 근거)

> 측정일 기준. 회색지대 gpt-4o 판정은 **고정**, 임베딩만 교체해 F1 비교.
> 재현: `.venv/Scripts/python.exe eval/run_embed_compare.py` (원본 로그: `eval/embed_compare.txt`, gitignore)

## 배경

서버 메모리 제약으로 **bge-m3(~2.3GB) 사용 불가**. 대안 임베딩을 정하기 위해,
같은 합성 평가셋(`eval/gold_questions.jsonl`, 35문항 / 정답 group 16개) 위에서
임베딩만 바꿔 코사인-only F1과 회색지대(gpt-4o) F1을 측정했다.

## 최종 비교표 (회색지대 판정 = gpt-4o 고정)

| 임베딩 | 코사인-only best F1 (thr / P / R) | 회색지대(gpt-4o) best F1 (밴드 / P / R) | 로컬 메모리 |
|---|---|---|---|
| **bge-m3** (참고, 서버 사용불가) | 0.716 (0.55 / .73 / .71) | **0.852** (0.50–0.62 / .96 / .77) | ~2.3GB ❌ |
| **OpenAI text-embedding-3-large** | 0.754 (0.40 / .85 / .68) | **0.780** (0.30–0.50 / .92 / .68) | 0 (API) |
| **OpenAI text-embedding-3-small** | 0.507 (0.30 / .49 / .53) | **0.737** (0.25–0.37 / .91 / .62) | 0 (API) |
| **KR-SBERT** (예전 로컬) | 0.561 (0.45 / .70 / .47) | **0.600** (0.35–0.50 / .94 / .44) | ~0.4GB |

> bge-m3 수치는 별도 측정(`eval/gray_4o.txt`)에서 가져온 참고값이다.

## 핵심 발견

### 1. bge-m3 밴드(0.50/0.62)를 다른 모델에 그대로 쓰면 회색지대가 거의 작동 안 함
코사인 스케일이 모델마다 달라, 기본밴드에선 대부분 쌍이 `< low`로 떨어져 자동 신규가 된다.

| 모델 | bge-m3 기본밴드(0.50/0.62) F1 | 모델 맞춤 밴드 F1 |
|---|---|---|
| KR-SBERT | 0.256 | 0.600 |
| 3-small | 0.162 | 0.737 |
| 3-large | 0.333 | 0.780 |

→ **임베딩을 바꾸면 밴드(low/high)는 반드시 그 모델 분포에 맞춰 재튜닝해야 한다.**

### 2. 코사인 분포(중앙값 p50)로 본 스케일·분리도

| 모델 | 같은그룹 p50 | 다른그룹 p50 | 분리도 |
|---|---|---|---|
| KR-SBERT | 0.402 | 0.256 | 보통 |
| 3-small | 0.282 | 0.201 | 나쁨(겹침 큼) |
| 3-large | 0.414 | 0.242 | 셋 중 가장 좋음 |

### 3. 임베딩이 약할수록 gpt-4o 기여가 커짐
- **3-large**: 코사인만 0.754 → 회색지대 0.780 (+0.026, LLM 기여 작음)
- **3-small**: 코사인만 0.507 → 회색지대 0.737 (**+0.230, LLM이 크게 구제**)
- **KR-SBERT**: 회색지대 써도 recall 0.44에 묶임 — 패러프레이즈 결합력이 근본적으로 약함(precision은 0.94로 높음)

## 운영 관점 (측정 외 사실, 결정에 영향)

- **OpenAI 임베딩은 "모든 질문"이 API를 탄다.** 로컬 임베딩(KR-SBERT/bge-m3)은 회색지대만 gpt-4o를 부르지만,
  OpenAI 임베딩은 질문당 임베딩 API 1콜 + 회색지대 시 gpt-4o 1콜 → 요청당 지연/비용 프로파일이 달라진다.
- **KR-SBERT는 ~0.4GB**로 서버 메모리에 무난히 들어가 bge-m3 메모리 문제를 해소한다. 대신 정확도가 제일 낮다.
- **3-large**가 성능상 bge-m3에 가장 근접(0.780 vs 0.852)하고 로컬 메모리 0.

## 측정 한계 (수치 신뢰도)

1. **밴드가 이 평가셋에 튜닝됨(test-set overfit).** 각 모델의 맞춤 밴드를 같은 35문항에서 골랐으므로 낙관적이다.
   bge-m3의 0.852도 동일하게 이 셋에 튜닝된 값이라 **상대 비교는 공정하나 절대값은 상한에 가깝다.**
2. **평가셋이 작다**(35문항, 같은그룹쌍 34개). F1 0.737 vs 0.780 같은 ~0.04 차이는 노이즈일 수 있다.
3. **KR-SBERT는 예전 운영의 형태소 키워드추출이 아니라, 현재 회색지대 아키텍처와 동일한 원문 임베딩(raw)으로 측정**했다(공정 비교 목적).
4. LLM 호출수는 모델 간 캐시 공유라 원본 로그의 "신규호출"만 표기 — 실배포 호출율과 다르다.

## 결론(측정이 말하는 것)

- 정확도 순위: bge-m3(0.852) > 3-large(0.780) > 3-small(0.737) > KR-SBERT(0.600).
- **메모리 0 + 로컬 임베딩 유지**를 최우선으로 하면 KR-SBERT가 후보(정확도는 최저, 재튜닝 필수).
- **정확도를 우선**하고 API 의존을 감수하면 3-large가 bge-m3에 가장 근접.
- 어느 쪽이든 **밴드 재튜닝은 필수**(위 발견 1).
